# Large Map Independent Eval Protocol

This protocol defines what counts as independent LLM edit evidence for the
large-map ATF format. It is intentionally stricter than the controlled Codex
trials in `docs/large-map-validation-report.md`.

## Purpose

The goal is to test whether an LLM can ergonomically edit large, detailed ATF
maps from reviewable source, without being handed the answer or relying on raw
generated block output.

An independent trial should prove all of the following:

- the model can locate the right semantic edit handle from a bounded brief,
- the model can edit ordinary ATF source in the prepared run tree,
- the edit stays in the expected group file,
- the source diff remains small enough for review,
- the edit expands into meaningful generated ATF,
- plan and core diagnostics stay clean.

## Independence Rules

A trial is independent only if the editing model is not the same active agent
that authored the benchmark or the controlled solution.

The model may receive:

- one generated task brief from `plan-eval-pack`,
- the prepared source tree named by that brief,
- normal tool output requested by the brief, such as `plan-diagnose`.

The model must not receive:

- controlled solution diffs from `target/validation-trials/model-eval-*`,
- copied snippets from the validation report's controlled examples,
- manual hints that specify exact rows to add,
- edits made by another model for the same task before it submits its own.

The operator may tell the model that diagnostics failed and ask for a fix, but
the retry count must be recorded.
`plan-eval-audit` enforces part of this automatically with an
`independence_hygiene` gate over generated handoff Markdown. It fails when a
pack contains known controlled-solution fingerprints such as `model-eval-*`,
`target-edit-*`, or `large-map-validation-report.md`.

## Setup

Generate a fresh pack with a run prefix that names the model or evaluation
batch:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-eval-pack \
  examples/large-map-validation/world.atf \
  examples/large-map-validation/edit-eval-tasks.tsv \
  target/validation-briefs/independent-MODEL-RUN \
  --run-prefix independent-MODEL-RUN \
  --independent \
  --isolated-handoffs \
  --model-surface MODEL-RUN \
  --operator OPERATOR \
  --date YYYY-MM-DD \
  --independence-notes "fresh pack; no prior solution snippets provided" \
  --write-initial-reports \
  --initial-min-passed 3 \
  --with-context \
  --context-lines 160
```

If repeating the same run after a failed setup, use `--overwrite-runs` only
before any model has edited the run directories.
The initial `status.md` and `audit.md` generated by this command are expected
to show no ready edits and no score artifact yet. They should still pass the
handoff, metadata, baseline-lock, and prepared-source-scope gates, which proves
the pack is ready to hand to independent model runs.

## Per-Task Model Instructions

Give each model run exactly one task directory from the pack:

```text
target/validation-briefs/independent-MODEL-RUN/handoffs/<task-id>/
```

That directory contains one `README.md` brief and one filtered `source/` tree.
The manifest points at `handoffs/<task-id>/source/world.atf`, so the scorer
checks exactly the tree handed to the model.

The model should:

1. edit only the `edited_world_atf` source tree named in the brief,
2. change only the intended `.atf` file unless the brief explicitly says
   otherwise,
3. avoid raw block commands when the task asks for plan/component/style rows,
4. run the brief's `diagnose_command`,
5. stop after diagnostics pass or after the recorded retry budget is exhausted.

## Readiness Check

Before full scoring, check the batch cheaply:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-eval-status \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN/manifest.tsv
```

Write the status artifact:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-eval-status-report \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN/manifest.tsv \
  target/validation-briefs/independent-MODEL-RUN/status.md
```

Status meanings:

- `missing`: the run tree or edited `world.atf` was not produced.
- `unedited`: the source tree is still identical to the base source.
- `wrong_file`: the model edited a file other than the expected group file.
- `ready`: the expected source file changed and no other `.atf` file changed.

Only `ready` rows should be fully scored.

## Full Score

Run the manifest scorer:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-edit-manifest \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN/manifest.tsv
```

Write the score artifact:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-edit-manifest-report \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN/manifest.tsv \
  target/validation-briefs/independent-MODEL-RUN/score.md
```

A row passes only when:

- changed source lines are within the row threshold,
- changed expanded ATF lines meet the row threshold,
- plan diagnostics report zero warnings,
- expanded core diagnostics report zero warnings,
- changed `.atf` files exactly match the expected changed file.

## Evidence Audit

After `status.md`, `score.md`, and `run-notes.md` are complete, audit the pack:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-eval-audit \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN \
  --min-passed 3 \
  --out target/validation-briefs/independent-MODEL-RUN/audit.md
```

The audit is intentionally stricter than the scorer. It checks that the pack
has the expected artifacts, run notes identify the model/surface, operator,
date, and independence notes, every manifest task has a retry row, handoff
Markdown matches `handoff-lock.tsv`, prepared run source matches
`baseline-lock.tsv` except for each task's expected changed file, prepared run
trees contain only reviewable ATF source files, handoff Markdown is free of
controlled-solution fingerprints, readiness was recorded, enough rows pass, and
the passed tasks cover Kikoshi-scale, castle/canal, and dense polish benchmark
families.

After at least two independent packs have been audited, check the cross-run
completion standard:

```text
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-eval-completion \
  examples/large-map-validation/world.atf \
  target/validation-briefs/independent-MODEL-RUN-A \
  target/validation-briefs/independent-MODEL-RUN-B \
  --min-runs 2 \
  --min-passed-per-run 3 \
  --out target/validation-briefs/independent-completion.md
```

This report fails unless enough pack audits pass and the completed packs name
distinct `Model or surface` values in `run-notes.md`.

## Evidence To Preserve

For each independent run, keep:

- the generated pack directory,
- `README.md`,
- `run-notes.md`,
- `handoff-lock.tsv`,
- `baseline-lock.tsv`,
- each task brief Markdown file,
- `manifest.tsv`,
- `status.md`,
- `score.md`,
- `audit.md`,
- the final `plan-edit-manifest` output,
- the edited run source trees named by `manifest.tsv`,
- a short note naming the model or surface used, date, operator, and retry
  count per task.

For the whole independent-eval batch, also keep the
`plan-eval-completion` Markdown report.

## Completion Standard

Independent edit evidence is strong enough for the large-map format claim when:

- at least two distinct model runs complete the batch,
- at least three of four tasks pass in each run,
- at least one passed task is in the 512x512 Kikoshi-scale group,
- at least one passed task is in the castle/canal group,
- at least one passed task is in the dense polish benchmark,
- failures are explained by status/scorer output rather than hidden manual
  judgment.

This still does not prove visual equivalence to a specific Mineplex map. It
does prove that the source format and eval harness support independent LLM
editing at target-class scale.
