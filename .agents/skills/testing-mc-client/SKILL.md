# Testing generated worlds in the real Minecraft client

The box has an offline-mode MC 26.1.2 client. Use it to prove generated worlds actually
load — file-format bugs (experimental-settings dialog, ignored spawn/gamemode) only
surface here, not in the generator's diagnostics.

## Client layout

- Launcher script: `~/mc/client26/run.sh` (uses `~/mc/jdk25` java, `--gameDir /home/ubuntu/mc/gamedir`,
  `--quickPlaySingleplayer <saves-dir-name>` at the end to auto-load a world)
- Saves: `/home/ubuntu/mc/gamedir/saves/<folder>/`
- Client log: `/home/ubuntu/mc/client26/logs/latest.log` (NOT gamedir/logs)
- F2 screenshots land in `/home/ubuntu/mc/gamedir/screenshots/`
- Kill a running instance before relaunch: `pkill -f 'minecraft\.client\.main'`
  (escaped dot so pkill doesn't match its own cmdline), then delete stale
  `saves/*/session.lock` files.

## Install a generated world

```sh
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar examples/.../world.atf /tmp/world-out
cp -r /tmp/world-out /home/ubuntu/mc/gamedir/saves/<new-folder-name>
```

Freshly copied saves have `LastPlayed=0` and sort to the BOTTOM of the Singleplayer
world list — scroll down to find them. The list entry shows parsed metadata
(gamemode, commands enabled, version) — a quick check that level.dat parsed.

## Force spectator mode via level.dat byte-patch

GameType is an NBT int tag: bytes `\x03\x00\x08GameType` followed by the 4-byte
big-endian int. Patch to 3 (spectator) so nobody dies and flight is possible:

```python
import gzip
p = 'saves/<world>/level.dat'
raw = gzip.decompress(open(p,'rb').read())
i = raw.find(b'\x03\x00\x08GameType') + len(b'\x03\x00\x08GameType')
raw = raw[:i] + (3).to_bytes(4,'big') + raw[i+4:]
open(p,'wb').write(gzip.compress(raw))
```

## A/B control technique

To prove "no warning dialog" is meaningful, also install a world generated by the
PRE-FIX code and open it first — it should still show the dialog. Build old code
without touching the worktree:

```sh
git worktree add /tmp/repo-old <pre-fix-commit>
(cd /tmp/repo-old && mvn -q -DskipTests package && java -jar target/anvil-tf-*-SNAPSHOT.jar <atf> /tmp/world-old)
git worktree remove /tmp/repo-old --force
```

## Input quirks

- Menus accept normal mouse clicks. In-game, mouse does NOT reach the GLFW window —
  use keyboard only: `slash` opens chat pre-filled with `/`, type command, Return.
- Useful commands: `/tp Devin <x> <y> <z> <yaw> <pitch>` (pitch 90 looks straight DOWN
  but in a void world shows skybox; tilt ~15-25 for landscape shots),
  `/time set 6000` for day, F3 debug overlay (shows XYZ/dimension), F2 screenshot.
- MC yaw: 0=south(+Z), 90=west(-X), 180=north(-Z), 270=east(+X). For a top-down shot
  facing south use yaw 0 pitch 90 — screen top is then north, screen left is east.
- View distance: integrated server follows `renderDistance` in
  `/home/ubuntu/mc/gamedir/options.txt` (default 4 = only ~64 blocks visible).
  Edit to 16 before launch for overview shots of large worlds.
- Launch: `cd ~/mc/client26 && setsid nohup ./run.sh > /tmp/mc-launch.log 2>&1 &`
  then wait ~25s for the GLFW window (check `wmctrl -l` for "Minecraft 26.1.2").
- Expected log noise in offline mode: RealmsAvailability / auth failures,
  SoundSystem ERROR (no audio device). These are not test failures.

## Pre-flight render check

Sources with a `plan {}` block must be expanded before `render`/`generate`:

```sh
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-expand examples/<x>/world.atf /tmp/x-expanded
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar render map /tmp/x-expanded/world.atf --out /tmp/x-map.png
java -jar target/anvil-tf-0.1.0-SNAPSHOT.jar plan-render examples/<x>/world.atf --out /tmp/x-plan.png
```

The map render catches holes/layout errors cheaply before launching the client.

## Post-load log check

After each in-client run, grep `/home/ubuntu/mc/client26/logs/latest.log` for
`Unknown registry key` — those mean the generated world contains block ids the
client doesn't know (e.g. renamed blocks like chain→iron_chain in 26.x). The client
substitutes air: authored blocks silently vanish even though the world "loads fine".
- On successful load, latest.log shows `Starting integrated minecraft server`,
  `Saving chunks for level .../minecraft:{overworld,the_nether,the_end}` (all three
  dims should appear), then `Devin logged in with entity id 1 at (x, y, z)`.

## Chunk-data verification (palette + block-entity checks)

Useful when a block places but may not render, or when a small block is hard to
see in screenshots. Hephaistos jars live under
`~/.m2/repository/io/github/jglrxavpok/hephaistos/` (needs common-*.jar,
fastutil, kotlin-stdlib on the classpath).

- Palette membership confirms the block was written: `RegionFile` →
  `getChunk(cx,cz).getBlockState(x,y,z)` (x/z chunk-local via `Math.floorMod`).
- Blocks rendered by a block entity (banners, signs, beds, chests, skulls) need
  a matching `minecraft:<type>` entry in `chunk.getTileEntities()` — palette
  entry without the BE id = invisible render. BE NBT x/y/z are world coords,
  so they double as exact `tp` targets for the visual check.
- Legacy 1.17-era saves (e.g. Greenfield reference) pop an upgrade-confirm
  dialog on load: click "I know what I'm doing!" → "Yes" to continue.
- When checking an interior, teleport INSIDE the structure bounds (spectator
  outside often renders the inside too dark to judge).

## Inspecting plan-authored builds

- `render`/`diagnose`/`build` do not parse `plan {}` blocks — run
  `plan-expand <world.atf> <outdir>` first, then point render/diagnose at the
  expanded `<outdir>/world.atf`.
- `render top <y>` shows blocks at exactly that y only; features sitting a
  half-step above street level (e.g. curb slabs) are at street_y+1, not
  street_y.
- Dense-row checks: when a target sits inside a continuous terrace, tps into
  the gaps land inside neighboring interiors. Use `plan-expand` `place` lines
  for the exact anchor x/z + surface y, then approach along the alley or
  roofline instead of dropping straight down.
- Waterline objects (boats, buoys): eye-level tps land submerged and aerial
  shots lose low dark hulls — verify via chunk-scan signature plus a
  hover-look-down shot from a few blocks above the surface.
